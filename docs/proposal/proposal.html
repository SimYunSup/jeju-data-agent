01구현 목표

문제: 데이터는 많은데, 도민이 쓰기 어렵다

찾기 어렵다

제주데이터허브에는 1,259종이 있지만 이름이 행정 용어(‘입도객’, ‘품종별 일일 거래 통계’)로 되어 있어 도민 표현(‘관광객’, ‘마늘 값’)으로는 찾기 어렵습니다. 517종은 외부 링크라 바로 열리지도 않습니다.

열어도 분석이 어렵다

수백 MB CSV, 인코딩 혼재, 따옴표 없이 쉼표가 들어간 행(예: 제주국제공항(대정,화순,일주서로)), API 요청 변수 등 엑셀만으로는 다루기 힘든 자료가 많습니다.

AI 답변은 믿기 어렵다

일반 챗봇은 데이터를 보지 않고 그럴듯한 숫자를 만들어 냅니다. 공공 데이터 서비스에서는 숫자 하나가 틀려도 신뢰를 잃습니다.

센터 데이터는 센터에서만

카드 이용·와이파이·버스 정류소별 이용 등 핵심 데이터는 반출이 제한되어, 센터 PC에서 바로 분석할 수 있는 도구가 필요합니다.

분석 주제

“도민의 생활·생업 질문을 제주 데이터로 답한다.” 특정 주제 하나를 고정하지 않고, 농업(감귤·월동채소 생산, 농산물 도매가격), 교통(버스 정류소·노선 이용), 관광(입도객·관광지 유입), 상권(카드 소비), 생활(충전소·의료기관) 등 데이터허브 8개 분야 전반을 하나의 Agent로 다룹니다.

AI를 활용한 데이터 분석 목표

목표AI가 하는 일측정 기준
데이터 탐색 자동화질문을 검색어로 바꾸고, 결과가 부족하면 표현을 바꿔 재검색, 상세(열·기간·요청 변수)를 보고 질문에 맞는 데이터 선택질문당 적합 데이터 적재 성공
분석 자동화필터·집계·기간 묶기·증감률·비중·이동평균·결합을 계획하고 오류 메시지를 읽고 스스로 수정도구 오류 후 자가 복구, 답변 완주율
결과 전달핵심 답 → 근거 표 → 차트 → 해석 → 한계 → 후속 질문 순의 쉬운 설명차트·한계·출처 포함 여부
신뢰성숫자는 계산 결과에서만, 데이터 기간·출처·결측 명시, 추측 금지답변 수치의 근거 대조 통과율

02서비스 제안

데이터 활용 개요

Agent는 제주데이터허브 공개 메타데이터로 만든 통합 카탈로그(허브 1,259종 + 센터 70종)를 먼저 검색합니다. 선택된 데이터는 형태에 따라 세 경로로 불러옵니다.

형태규모불러오는 방법필요한 것
FILE670여 종데이터 상세의 첨부 CSV/XLSX를 내려받아 캐시없음(즉시)
API93종요청 변수를 Agent가 채우고 페이지 단위 수집사용자 프로젝트 키
센터70종센터 PC 폴더(CENTER_DATA_DIR)의 파일 자동 연결센터 방문
LINK517종자동 적재 불가 → 출처 링크로 안내—

핵심 기능

① 말로 묻는 데이터 검색

한국어 2-gram 검색 + 도민 표현 동의어(관광객↔입도객, 가격↔시세). 형태소 분석기·GPU 없이 센터 PC에서 0.1초 안에 1,329종 검색.

② 스스로 분석하는 Agent

검색 → 상세 확인 → 적재 → 분석 → 차트 → 답변을 도구 호출로 자율 수행. 오류가 나면 열 이름·변수를 고쳐 재시도.

③ 숫자 자동 검증·자기 수정

답변 속 집계 숫자(수량·금액·비율, ‘228곳’ 같은 개수 포함)를 뽑아 계산 결과와 대조(반올림, ‘3.6만’, ‘5억 9,706만’, 백만원 단위 열 인식). 날짜·순위·질문에 나온 조건 숫자는 제외. 근거 없는 숫자가 있으면 Agent가 한 번 스스로 다시 계산하거나 지우고, 그래도 남으면 화면에 경고.

④ 재현 가능한 결과

답변마다 보고서·근거 표(CSV)·차트·출처 기록·같은 결과를 다시 계산하는 파이썬 코드를 ZIP으로 제공.

⑤ 깨진 원본도 견고하게

인코딩 자동 판별, 따옴표 없는 쉼표 행 복구, 날짜·숫자 자동 변환, 정류소ID 같은 코드 보존.

⑥ 센터 데이터 연결

반출 불가 데이터도 센터 PC 폴더에 두면 같은 화면에서 분석. 결과(집계)만 반출 절차로.

편의성

  • 설치 없이 더블클릭: run.bat이 파이썬·라이브러리를 자동 설치하고 브라우저 화면을 엽니다.
  • 예시 질문 버튼·진행 상황 표시: “🔎 데이터 찾기 → 📥 불러오기 → 🧮 분석 → 📊 차트”가 실시간으로 보여 기다림이 불안하지 않습니다.
  • 이어 묻기: 같은 대화에서 “그중 상위 3곳만 월별로”처럼 이어 물으면 불러온 데이터를 재사용합니다.
  • AI 없이도 쓰는 데이터 찾아보기 탭: 키가 없어도 목록 검색·미리보기가 됩니다.

분석 데이터 활용 방안

검증 방법

  • 수치 대조와 자기 수정: 답변의 집계 숫자를 세션의 결과 표·도구 관측값과 대조합니다. 개발 중 모델이 직접 뺄셈한 “8.3만 톤 감소”, “1위와 2위 차이 126,633명”을 근거 없음으로 잡았고, 이제는 finish 단계에서 이런 숫자를 Agent에 되돌려 analyze로 계산해 표에 남기거나 답에서 빼도록 한 번 스스로 고치게 합니다.
  • 처음 보는 질문으로 심사 기준 점검: 대표 질문 밖의 질문 6개를 새 환경에서 돌려 결과 표와 하나씩 대조했습니다. 숫자는 표에 있지만 뜻이 틀린 경우(빠진 달을 건너뛴 ‘전월 대비’, 증감 인원을 ‘증감률’로 이름 붙인 열, 기준 미적용 항목을 뺀 ‘모두 적합’)를 찾아, 증감률은 날짜 기준 바로 앞 기간과만 비교하고 비율 이름의 열은 나눗셈으로만 만들도록 엔진에서 막았습니다. 숫자 대조만으로는 문장의 뜻까지 보장하지 못하므로, 순위·전체 판단은 후보 전체를 집계한 표에서만 말하도록 지시문을 강화했습니다.
  • 재현: 결과 ZIP의 analysis.py를 실행하면 데이터허브에서 원본을 다시 받아 같은 결과 표를 출력합니다(단위 테스트로 생성 코드 = 엔진 결과 동일성 확인). 원본 표는 재배포하지 않고 결과 표만 동봉합니다.
  • 단위 테스트 25개: 분석 엔진, 날짜 필터, 기간 정렬 증감률, 비율 열 검사, 코드 열 보존, 수치 표기(반올림·만/억·혼합 표기·백만원 단위·노선번호 제외·개수 단위), API 페이지 수집·키 오류, 가짜 LLM으로 돌리는 Agent 루프(자기 수정·깨진 인자 복구).

한계와 대응

  • 데이터허브 다수 자료가 2021~2025년 갱신분 → 답변마다 실제 수록 기간을 밝히도록 강제.
  • API 데이터는 사용자 키가 필요 → 키가 없으면 같은 주제의 FILE·센터 데이터를 찾거나 발급 방법을 안내.
  • 모델 품질에 따라 데이터 선택이 달라질 수 있음 → 계산은 엔진이, 숫자는 검증이 지키는 구조로 위험을 숫자 오류가 아닌 ‘덜 좋은 데이터 선택’으로 한정.

센터 활용 방안

센터 분석실 PC에 설치해 방문 도민의 첫 분석 도구로 쓰고, 센터 방문 데이터 폴더를 연결해 반출 불가 데이터도 같은 화면에서 분석합니다. 질문·데이터 선택 기록(provenance.json)은 어떤 데이터가 자주 쓰이는지 보여 주어 데이터 개방·정비 우선순위 판단에 활용할 수 있습니다.
