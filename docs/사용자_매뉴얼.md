# 제주 데이터 길잡이 — 설치·실행·사용자 매뉴얼

## 1. 준비물

| 항목 | 내용 |
|---|---|
| PC | Windows 10/11(센터 PC 최소사양 i7-8700 / GTX 1060 / RAM 32GB에서 동작), macOS, Linux |
| 인터넷 | 제주데이터허브 데이터 내려받기와 AI 모델 호출에 필요 |
| AI 모델 | OpenAI 호환 Chat Completions + 도구 호출(function calling)을 지원하는 모델 1개 |
| (선택) 데이터허브 프로젝트 키 | API 데이터 93종을 쓰려면 필요. 없어도 파일 데이터 670여 종은 그대로 분석 |
| (선택) 센터 데이터 폴더 | 제주빅데이터센터 방문 데이터(CSV/XLSX)를 분석할 때 |

GPU는 필요 없습니다. 분석은 CPU(pandas)로 하고, AI 모델은 원격 API를 씁니다.
센터 PC에서 인터넷 AI를 쓸 수 없다면 Ollama 같은 로컬 모델 서버를 `LLM_BASE_URL`로 지정할 수 있습니다(7장).

## 2. 설치·실행

### Windows(센터 PC)
1. 제출 ZIP을 원하는 폴더(예: `C:\jeju-data-agent`)에 풉니다.
2. `run.bat`을 더블클릭합니다.
   - 처음 실행이면 파이썬 패키지 관리자 `uv`를 자동 설치하고, `.env` 설정 파일을 메모장으로 엽니다.
   - 3장을 보고 `.env`를 채워 저장한 뒤 `run.bat`을 다시 실행합니다.
3. 브라우저에서 `http://localhost:8501`이 열립니다(자동으로 안 열리면 주소창에 직접 입력).

처음 실행 때는 파이썬 3.12와 라이브러리를 자동으로 내려받느라 몇 분 걸립니다. 두 번째부터는 바로 뜹니다.

### macOS / Linux
```bash
./run.sh            # 처음이면 .env를 만들고 멈춤 → .env 채운 뒤 다시 실행
```

### 명령줄(재현·자동화용)
```bash
uv sync                                          # 의존성 설치(uv.lock 그대로)
uv run jeju-data-agent ask "서귀포시 감귤 생산량 추이"   # 질문 하나 → outputs/ 결과 폴더
uv run jeju-data-agent search "버스 정류소"             # 데이터 찾기(AI 불필요)
uv run jeju-data-agent refresh-catalog                 # 데이터허브 목록 새로 받기
uv run pytest                                          # 단위 테스트
```

## 3. `.env` 설정

`.env.example`을 복사해 `.env`를 만들고 채웁니다(`run.bat`이 자동으로 복사해 줍니다).

| 변수 | 필수 | 설명 | 예 |
|---|---|---|---|
| `LLM_BASE_URL` | ✅ | OpenAI 호환 API 주소 | `https://api.openai.com/v1` |
| `LLM_MODEL` | ✅ | 모델 이름 | 제공사 모델 ID |
| `LLM_API_KEY` | ✅* | 모델 API 키(*로컬 서버는 아무 값) | `sk-...` |
| `JEJU_DATAHUB_PROJECT_KEY` | | 제주데이터허브 프로젝트 키(4장) | 32자리 키 |
| `CENTER_DATA_DIR` | | 센터 방문 데이터 폴더(5장) | `D:\center-data` |
| `DATA_DIR` / `OUTPUT_DIR` | | 캐시·결과 폴더 | 기본 `./data`, `./outputs` |
| `AGENT_MAX_STEPS` | | 질문 하나당 AI 도구 사용 최대 횟수 | 기본 14 |

API 키는 화면·보고서·로그에 출력되지 않습니다. `.env`는 다른 사람과 공유하지 마세요.

### 심사·평가용 AI 설정 (평가 기간 전용)

전문가 평가에서는 아래 세 줄을 `.env`에 그대로 붙여 넣으면 별도 키 발급 없이 실행됩니다.
개발·시나리오 실측에 쓴 것과 같은 모델입니다. 이 키는 평가 종료 후 폐기합니다.

```
LLM_BASE_URL={{EVAL_LLM_BASE_URL}}
LLM_MODEL={{EVAL_LLM_MODEL}}
LLM_API_KEY={{EVAL_LLM_API_KEY}}
```

접속하는 외부 주소: AI 모델 `{{EVAL_LLM_HOST}}`, 제주데이터허브 `jejudatahub.net`·`open.jejudatahub.net`,
최초 설치 때 `astral.sh`(uv)·`github.com`(파이썬 3.12)·`pypi.org`·`files.pythonhosted.org`(라이브러리).

## 4. 제주데이터허브 API 키(프로젝트 키) 발급 — 선택

API 형태 데이터(버스 정류소별 일일 이용자, 농산물 일일 거래 통계, 읍면동 유동인구 등)를 쓰려면 필요합니다.

1. [jejudatahub.net](https://jejudatahub.net) 회원가입·로그인
2. **마이페이지 → 프로젝트 관리 → 프로젝트 만들기**(이름 자유)
3. 쓰려는 API 데이터 상세 페이지에서 **‘프로젝트 담기’**로 2번 프로젝트에 추가
   (프로젝트에 담지 않은 데이터는 키가 있어도 거부됩니다)
4. 프로젝트 상세 페이지의 **프로젝트키**를 `.env`의 `JEJU_DATAHUB_PROJECT_KEY`에 붙여넣기

API마다 하루 호출 한도(1,000~3,000회)가 있습니다. 한 번 불러온 표는 같은 대화 안에서 다시 호출하지 않습니다.

## 5. 제주빅데이터센터 방문 데이터 쓰기 — 센터 PC

센터에서만 볼 수 있는 데이터(카드 이용 현황, 버스 정류소별 이용 현황, 와이파이 이용 현황 등 70종)는
인터넷으로 받을 수 없으므로, 센터 PC에서 내려받은 CSV/XLSX를 한 폴더에 모은 뒤 `CENTER_DATA_DIR`로 지정합니다.

- 파일 이름에 **데이터 이름**(예: `버스 정류소별 이용 현황.csv`) 또는 **테이블명**(예: `tb_card_korean_usage.csv`)이 들어가면 자동으로 연결됩니다.
- 반출 불가 데이터는 센터 밖으로 가져가지 마세요. 분석 결과(집계 표·차트)만 센터 반출 절차를 따르세요.

## 6. 화면 사용법

| 영역 | 기능 |
|---|---|
| 왼쪽 메뉴 | 설정 상태(AI 모델·API 키·센터 폴더), 예시 질문 버튼, 새 대화 |
| 💬 질문하기 | 평소 말투로 질문 → 진행 상황(데이터 찾기·불러오기·분석·차트)이 실시간으로 보임 → 답변·차트 |
| 답변 아래 | 수치 검증 결과, 한계, 근거 데이터와 출처(원본 링크), 분석 과정, **결과 내려받기(ZIP)** |
| 🗂️ 데이터 찾아보기 | AI 없이 데이터 목록 검색·상세 보기·미리 불러오기 |

질문 요령
- 장소·기간·대상을 넣으면 정확해집니다: “2024년 깐마늘 월별 도매가격”, “서귀포시 읍면동별 감귤 농가 수”.
- 같은 대화에서 이어서 물으면 앞에서 불러온 데이터를 재사용합니다: “그중 상위 3곳만 월별로 보여줘”.

결과 ZIP 구성: `report.md`(답변·차트·한계·출처·수치 검증), `R*.csv`(근거 표), `chart*.png`,
`analysis.py`(같은 결과를 다시 계산하는 파이썬 코드), `provenance.json`(데이터 출처·분석 단계 기록).

## 7. 로컬 AI 모델(인터넷 AI 키 없이)

센터 PC 최소사양(i7-8700 / GTX 1060 6GB / RAM 32GB)에서 그대로 돌아가도록 준비 스크립트를 넣었습니다.

| 환경 | 실행 |
|---|---|
| Windows | `setup_local_ai.bat` 더블클릭 → 끝나면 `run.bat` |
| macOS/Linux | `./setup_local_ai.sh` (Ollama는 먼저 설치) → `./run.sh` |

스크립트가 하는 일
1. [Ollama](https://ollama.com) 설치(Windows: `winget`)
2. `OLLAMA_CONTEXT_LENGTH=16384` 설정 후 Ollama 재시작 — 기본 컨텍스트로는 도구 결과가 잘립니다
3. `qwen3.5:4b` 내려받기(약 3.3GB, 6GB GPU에 컨텍스트까지 올라감). 다른 모델: `setup_local_ai.bat qwen3:8b`
4. `.env`의 `LLM_BASE_URL=http://127.0.0.1:11434/v1`, `LLM_MODEL=qwen3.5:4b`, `LLM_API_KEY=ollama` 설정

로컬 모델에 맞춘 처리: 오래된 도구 결과는 앞부분만 다시 보내 컨텍스트를 아끼고, 모델이 빈 응답으로 멈추면 다음 행동을
다시 요청하며, 근거 없는 숫자는 한 번 스스로 고치게 합니다. 그래도 4B 모델은 데이터 선택·해석이 원격 모델보다 단순하므로
심사·실사용에는 가능하면 원격 AI 키(3장)를 권장합니다.

## 8. 오류·제약사항

| 증상 | 원인·해결 |
|---|---|
| “AI 모델이 설정되지 않았습니다” | `.env`의 `LLM_BASE_URL`·`LLM_MODEL` 확인 후 재실행 |
| “API 데이터는 프로젝트 키가 필요합니다” | 4장 발급. 키 없이도 같은 주제의 FILE 데이터가 있으면 Agent가 그쪽을 씁니다 |
| “HTTP 403” (API) | 해당 데이터를 프로젝트에 ‘담기’ 하지 않음, 또는 일일 한도 초과 |
| “외부 링크 데이터라 자동으로 불러올 수 없습니다” | 데이터허브 LINK형(517종)은 외부 사이트로 연결돼 자동 적재 불가 |
| 처음 질문이 오래 걸림 | 대용량 파일(예: 버스정류소 이용 인원 624MB) 최초 다운로드. 이후 `data/cache`에서 재사용 |
| “근거 표에서 확인되지 않은 수치” 경고 | AI가 쓴 숫자가 계산 결과에 없음. 해당 숫자는 믿지 말고 분석 과정을 확인 |

알려진 제약
- 데이터허브 자료 다수는 2021~2025년 갱신분입니다. Agent는 답변에 데이터 기간을 밝히지만 최신 현황을 대신하지 않습니다.
- 원본 파일의 깨진 행(따옴표 없이 쉼표가 들어간 이름 등)은 자동 복구하고, 복구 못 한 행 수는 답변의 한계로 알립니다.
- HWP·PDF·이미지 형식 첨부와 LINK형 데이터는 분석 대상이 아닙니다.
